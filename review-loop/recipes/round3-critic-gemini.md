**Finding 1 [HIGH] — Question (1): Gemini (`agy`) explicitly allows `command(find)` inside a `bwrap` fence that keeps full network access and `--dev-bind / /` (writable `$HOME`), allowing arbitrary code execution, live `office` daemon read/write, and persistent `$HOME` modification**
- **Where:** `readers.md` ("The fence" and "Reading, or running code" — Gemini recipe).
- **Failure scenario:** The outer `bwrap` uses `--dev-bind / /` without `--unshare-net` and without `--ro-bind $HOME $HOME`, leaving `$HOME` writable and the unauthenticated `office` HTTP daemon (`http://127.0.0.1:7701`) reachable. Gemini's `--settings` allows `command(find)` and only denies `command(office)`, `command(curl)`, and `command(sudo)`. Without pipes or shell operators, a Gemini reader can run:
  1. `find . -maxdepth 0 -exec python3 -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:7701/work?read=trail').read().decode())" \;` (or POST to `/remember`, `/forget`, `/work/close`, `/issues/open` via `python3`, `bun`, or `wget`) to read or corrupt the live office database through the daemon.
  2. `find . -maxdepth 0 -fprintf /home/<user>/.bashrc "..."` or `find /home/<user>/... -delete` (or `-exec sh -c ... \;`) to write or delete arbitrary files in `$HOME` (e.g., `~/.bashrc`, `~/.ssh/authorized_keys`, `~/.config/systemd/user/`, or `<round>/<other-reader>.report`), outliving the run.


**Finding 2 [HIGH] — Question (1): Neither `FENCE` nor Claude's `<round>/run` isolates `/proc` (`--unshare-pid --proc /proc`) or `/run/user/$UID`, allowing readers to read `memory.db` straight through `/proc/<pid>/root` and escape the sandbox via `systemd --user`**
- **Where:** `readers.md` ("The fence" and "Reading, or running code" — `<round>/run`).
- **Failure scenario:** Both `bwrap` invocations use `--dev-bind / /` without `--unshare-pid` or `--proc /proc`.
  1. **Direct read of `memory.db`, `office.log`, and hidden transcripts (even by Gemini using only `find` and `cat`):** Same-UID host processes (the `office` daemon, `systemd --user`, and the parent author agent) remain visible in `/proc`. On Linux, `/proc/<host-pid>/root/...` and `/proc/<office-pid>/fd/<n>` check `PTRACE_MODE_READ_FSCREDS` (which succeeds for same-UID dumpable processes even under `yama.ptrace_scope=1`) and jump directly into the **host mount namespace**, bypassing every `--tmpfs` in `FENCE`. A Gemini reader using only allowed `find` and `cat` can run `cat /proc/<office-pid>/root/home/<user>/.local/share/agent-office/memory.db` (or `office.log`).
  2. **Full sandbox & persistence escape via `/run/user/$UID` (`systemd --user`):** `/run/user/$UID` lives outside `$HOME`, so `--dev-bind / /` leaves `/run/user/$UID/systemd/private` and `/run/user/$UID/bus` writable inside both `FENCE` and Claude's `<round>/run`. Filesystem Unix domain sockets ignore `--unshare-net`, so code executed under `<round>/run` (or `FENCE`) can invoke `systemd-run --user ...` (or D-Bus) to run commands on the host with full network access to `127.0.0.1:7701`, write access to `$HOME` and `<repo>`, and persistence after `bwrap --die-with-parent` exits. Any host-PID-namespace code can also `kill -9 <office-pid>`.

**Finding 3 [HIGH] — Question (1): Unhidden user configs (`~/.codex/config.toml`, `~/.gemini/config/{mcp_config,hooks}.json`, `~/.claude/settings.json`), transcripts (`~/.grok`, `history.jsonl`), and `--ro-bind <repo> <repo>` leak office data and run unsandboxed hooks/MCP servers**
- **Where:** `readers.md` ("The copy", "The fence", and "Reading, or running code").
- **Failure scenario:**
  1. **Hooks and MCP servers run in the CLI parent process (which has network access to `127.0.0.1:7701` and writable `$HOME` in `FENCE`):** Only Claude disables MCP (`--strict-mcp-config`), and even Claude still reads `$HOME/.claude/settings.json` (user lifecycle hooks) and `$HOME/.claude/CLAUDE.md`. Codex still reads `$HOME/.codex/config.toml` (spawning configured MCP servers outside `-s read-only`/`workspace-write`, and inheriting `sandbox_workspace_write.network_access = true` if configured) and `$HOME/.codex/AGENTS.md`. Gemini only overlays `~/.gemini/config/rules` and `settings.json`, leaving `~/.gemini/config/mcp_config.json` and `~/.gemini/config/hooks.json` active. If the machine has an `office` MCP server or session hook configured, the reader reaches the live office daemon automatically.
  2. **Unhidden office-quoting files and `<repo>`:** `FENCE` omits `$HOME/.grok` (Grok transcripts), `$HOME/.claude/history.jsonl`, `$HOME/.codex/history.jsonl`, `$HOME/.codex/state_*.sqlite`, and any custom `$OFFICE_DB` path (`src/paths.ts` allows `OFFICE_DB` outside `OFFICE_HOME`). Furthermore, `--ro-bind <repo> <repo>` leaves the entire live `<repo>` readable (its exact path is advertised by the `<copy>/node_modules -> <repo>/node_modules` symlink), so Codex, Gemini, and running-code Grok can read `<repo>/AGENTS.md`, `<repo>/review-loop/` (plans, ledgers, office notes, and built work — breaking blind-solver isolation), and `..` (`<round>/`), where parallel readers' briefs, logs, and reports sit.

**Finding 4 [MEDIUM] — Question (1): Host `/tmp` and `/var/tmp` are shared read-write instead of isolated with `--tmpfs`, letting readers leave persistent files and poison sibling/host state**
- **Where:** `readers.md` ("The fence" and `<round>/run`).
- **Failure scenario:** Neither `FENCE` nor `<round>/run` mounts `--tmpfs /tmp --tmpfs /var/tmp`. Codex (`-s workspace-write`), Grok (both `strict` and `review-loop-reader`), Claude (`<round>/run`), and Gemini write to the real host `/tmp` (and Grok/Claude/Gemini to `/var/tmp`, which survives reboots). A reader can leave persistent payloads or poison shared `/tmp` caches/sockets read by parallel blind readers or later host runs, and can read anything the author agent left in `/tmp` (such as the `<tmp>` folder used to build a blind solver's `git archive`).


**Finding 5 [HIGH] — Question (2): Nested sandboxes (`<round>/run`, `codex`, `grok` inside outer `bwrap`) fail on Ubuntu 24.04+ AppArmor, setuid-`bwrap` distros, and Linux containers; `bwrap` and `jq` are missing on many default Linux installs**
- **Where:** `readers.md` ("The fence", "Reading, or running code", and "Getting the report").
- **Failure scenario:**
  1. **Nested namespaces:** Outer `FENCE` runs `bwrap`, which sets `PR_SET_NO_NEW_PRIVS=1` and enters a user namespace. On hardened Debian/RHEL machines where `bwrap` relies on setuid-root (`unprivileged_userns_clone=0`), `no_new_privs` prevents inner `bwrap` (`<round>/run`) from using setuid while the kernel blocks unprivileged `CLONE_NEWUSER` for Claude, Codex, and Grok's inner sandboxes (`Operation not permitted`). On Ubuntu 24.04+ (`apparmor_restrict_unprivileged_userns=1`), adding a confined `/etc/apparmor.d/bwrap` profile permits `bwrap` itself, not the `codex` or `grok` binaries that create their own inner user/network namespaces. Inside standard Docker/CI/Podman containers, outer `bwrap` fails immediately.
  2. **Missing default tools:** Neither `bubblewrap` nor `jq` (nor `rsync` on minimal images) is preinstalled on standard Ubuntu Server, Debian, Fedora, or Arch installs; without `jq`, report extraction fails after Grok, Claude, or Gemini finishes.

**Finding 6 [HIGH] — Question (2) & (1): Gemini's `--ro-bind <round>/empty.json $HOME/.gemini/antigravity-cli/settings.json` leaves a persistent 0-byte invalid `settings.json` on any computer that did not already have one**
- **Where:** `readers.md` ("The fence" — Gemini `<extras>`).
- **Failure scenario:** On a fresh Linux machine where `agy` has never written `~/.gemini/antigravity-cli/settings.json`, `bwrap --dev-bind / / ... --ro-bind <round>/empty.json $HOME/.gemini/antigravity-cli/settings.json` creates a 0-byte mountpoint file at `~/.gemini/antigravity-cli/settings.json` on the real host disk, mounts `empty.json` (`{}`) over it during the run, and unmounts on exit. That 0-byte file outlives the run (unmentioned by "Left behind", which only warns about empty `--tmpfs` folders) and is invalid JSON, breaking subsequent normal `agy` invocations on the host.

**Finding 7 [MEDIUM] — Question (2): Symlinked top-level `node_modules`/`.venv` and read-only `$HOME` (`$HOME/.cache`) break non-Bun ecosystems (`go test`, `cargo test`, Python editable `.venv`, monorepos) and repos outside `$HOME`**
- **Where:** `readers.md` ("The copy" and "Reading, or running code").
- **Failure scenario:**
  1. **Read-only `$HOME/.cache` / `$HOME/.cargo`:** Codex (`-s workspace-write`), Grok (`read_only = ["<home>"]`), and Claude (`<round>/run` `--ro-bind $HOME $HOME`) block writes to `$HOME/.cache` and `$HOME/.cargo` without setting `XDG_CACHE_HOME=/tmp`, `GOCACHE=/tmp/...`, or `CARGO_HOME`. Running `go test`, `cargo test`, or Python/ML tools that write to `~/.cache` fails on first run with `Read-only file system`.
  2. **Editable `.venv` and workspace symlinks import `<repo>` instead of `<copy>`:** In Python repos (`pip install -e .` / `uv` / `poetry`) and JS/TS workspace monorepos (`node_modules/@org/pkg -> ../packages/pkg`), symlinking `<copy>/.venv` or `<copy>/node_modules` to `<repo>` resolves imports back into `<repo>` rather than `<copy>` (and `--exclude=node_modules` strips nested `packages/*/node_modules` while `ln -s` only links the root).
  3. **`<repo>` realpath outside `<home>`:** If `<repo>` lives at `/work/repo`, `/srv/repo`, or `~/Projects -> /data/Projects`, Grok's `extends = "strict"` + `read_only = ["<home>"]` blocks reading `<copy>/node_modules -> <repo>/node_modules`.

**Finding 8 [MEDIUM] — Question (2): Passing `<brief>` in `argv` hits Linux's hardcoded 128 KiB `MAX_ARG_STRLEN` (`E2BIG`) on Grok and Gemini; `timeout 20m` without `-k` can hang indefinitely; unquoted `$FENCE` breaks on paths with spaces**
- **Where:** `readers.md` ("The fence" and "Reading, or running code").
- **Failure scenario:**
  1. Grok (`-p "$(cat <brief>)"`) and Gemini (`--print="$(cat <brief>)"`) pass the entire brief in a single `execve` argument. When the brief includes a git diff (as "The copy" requires for linked worktrees) or test output, exceeding Linux's 128 KiB `MAX_ARG_STRLEN` fails immediately with `Argument list too long`.
  2. `timeout 20m` without `-k` (`--kill-after`) only sends `SIGTERM`; a reader or test child ignoring `SIGTERM` hangs past 20 minutes without producing `<reader>.status = 124`.
  3. Unquoted `bwrap $FENCE` and unquoted paths in `<round>/run` (`--ro-bind $HOME $HOME --bind <copy> <copy>`) fail whenever `<repo>`, `$OFFICE_HOME`, or `$HOME` contains spaces or glob characters.


**Finding 9 [HIGH] — Question (3): Remove the Gemini (`agy`) reader recipe (eliminating `<extras>`, `<round>/empty.json`, Gemini's 7-command brief restriction, and its multi-run probe)**
- **Where:** `readers.md` ("The fence" lines 50–53, "Reading, or running code" lines 62, 71, 86–88).
- **Why removable without losing the goal & concrete failure scenario:** The goal requires readers that *run code*, *cannot reach the office whatever they decide*, and *leave a usable report even when they fail*. Gemini satisfies none of the three: it cannot run code (`none: it reads only`), can reach `127.0.0.1:7701` and write `$HOME` via `find -exec` (Finding 1), and aborts with `no output produced` the first time the model uses a pipe, `echo`, `rg`, or `git` — while `--ro-bind <round>/empty.json .../settings.json` leaves a corrupt 0-byte `settings.json` on hosts that had none (Finding 6). Removing Gemini as a reader removes `<extras>`, `empty.json`, and the special brief rule without losing any goal capability (keep only the `--tmpfs` hides of `$HOME/.gemini/...` in `FENCE` so *other* readers cannot read author Gemini transcripts).

**Finding 10 [MEDIUM] — Question (3): Remove `.git` from `<copy>` unconditionally (`--exclude=.git` in `rsync`), removing the manual linked-worktree branch and `-path ./.git -prune`**
- **Where:** `readers.md` ("The copy" lines 19–27, "If the reader may write" line 108).
- **Why removable without losing the goal & concrete failure scenario:** `readers.md` already drops `.git` for linked worktrees and blind solvers (`git archive`), and passes `--skip-git-repo-check` to Codex — showing `.git` history is unnecessary in `<copy>`. Keeping `.git` in `<copy>` causes three failures: (1) committed `AGENTS.md`, `CLAUDE.md`, and frozen `review-loop/<change>/PLAN.md` files remain readable inside `<copy>/.git/objects` (even to Grok `strict` and Claude `Read`/git), defeating `rsync --exclude`; (2) multi-GB `.git` packfiles are duplicated into `~/.cache` for every parallel reader; and (3) forgetting the manual prose check *"If `<repo>/.git` is a file"* leaves `<copy>/.git` pointing into the live main repository.

**Finding 11 [LOW] — Question (3): Remove Grok's separate "Reading only" (`--sandbox strict`) row in favor of one Grok profile always treated as copy-writable**
- **Where:** `readers.md` ("Reading, or running code" lines 60, 69, 95, 130).
- **Why removable without losing the goal & concrete failure scenario:** Grok's `--sandbox strict` (`--always-approve`) is **not** read-only: as line 130 admits (`./PROBE_COPY` exists under Grok's `strict`), it can run commands and write to `<copy>`, `/tmp`, and `/var/tmp`. Listing `--sandbox strict` under "Reading only" misleads the caller into skipping the "If the reader may write" `sha256sum` check when Grok modifies files it is judging, while `strict`'s only extra restriction (blocking reads of `$HOME`) breaks helper binaries under `$HOME` and forces `<brief>` onto `argv` (`-p "$(cat <brief>)"`), crashing with `E2BIG` at 128 KiB.

That 0-byte file outlives the run (unmentioned by [Left behind](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L171-L174), which only warns about empty `--tmpfs` folders) and is invalid JSON, breaking normal `agy` runs on that machine afterwards.

### Finding 7 [MEDIUM]: Read-only `$HOME/.cache` and root-only `node_modules`/`.venv` symlinks break non-Bun toolchains, editable Python installs, monorepos, and checkouts outside `$HOME`
- **Where:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L18-L23) and [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L67-L85).
- **Concrete failure scenario:**
  1. **Read-only `$HOME/.cache` / `$HOME/.cargo`:** Codex (`-s workspace-write`), Grok (`read_only = ["<home>"]`), and Claude (`<round>/run` `--ro-bind $HOME $HOME`) block writes to `$HOME/.cache` and `$HOME/.cargo` without redirecting `XDG_CACHE_HOME`, `GOCACHE`, or `CARGO_HOME` to `/tmp`. Running `go test`, `cargo test`, or Python/JS tools that cache under `~/.cache` fails on first run with `Read-only file system`.
  2. **Editable `.venv` and workspace symlinks test `<repo>` instead of `<copy>`:** In Python projects with editable installs (`pip install -e .` / `uv` / `poetry` `.pth` files) or JS workspace monorepos (`node_modules/@org/pkg -> ../packages/pkg`), symlinking `<copy>/.venv` or `<copy>/node_modules` to `<repo>` resolves imports to `<repo>` rather than `<copy>`. Additionally, `rsync --exclude=node_modules --exclude=.venv` strips nested `packages/*/node_modules` while `ln -s` only restores the top-level link.
  3. **`<repo>` outside `<home>`:** If `<repo>`'s realpath is outside `<home>` (e.g., `/work/repo`, `/srv/repo`, or `~/Projects -> /data/Projects`), Grok's `extends = "strict"` + `read_only = ["<home>"]` blocks reading `<copy>/node_modules -> <repo>/node_modules`.

### Finding 8 [MEDIUM]: Passing `<brief>` in `argv` hits Linux's hardcoded 128 KiB `MAX_ARG_STRLEN` (`E2BIG`) on Grok and Gemini; `timeout 20m` without `-k` hangs when `SIGTERM` is ignored; unquoted `$FENCE` breaks on spaces
- **Where:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L39-L44) and [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L60-L85).
- **Concrete failure scenario:**
  1. Grok (`-p "$(cat <brief>)"`) and Gemini (`--print="$(cat <brief>)"`) pass the whole brief as a single `execve` argument. When the brief includes a git diff (required by [The copy](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L25-L27) for linked worktrees) or test output, any brief ≥ 128 KiB (`MAX_ARG_STRLEN`) fails immediately with `Argument list too long`.
  2. `timeout 20m` without `-k` (`--kill-after`) only sends `SIGTERM`; if a hung CLI or child test process traps/ignores `SIGTERM`, `timeout` never escalates to `SIGKILL` and never writes `124` to `<reader>.status`.
  3. Unquoted `bwrap $FENCE` and unquoted paths inside `<round>/run` (`--ro-bind $HOME $HOME --bind <copy> <copy>`) split and fail whenever `<repo>`, `$OFFICE_HOME`, or `$HOME` contains spaces or glob characters.

## (3) What in the design could be removed without losing the goal

### Finding 9 [HIGH]: Remove the Gemini (`agy`) reader recipe (removing `<extras>`, `<round>/empty.json`, Gemini's 7-command brief rule, and its multi-run probe)
- **Where:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L50-L55), [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L62-L71), and [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L86-L88).
- **Concrete failure scenario & why removable:** Against the goal (*"start readers that run code, cannot reach the office whatever they decide, and leave a usable report even when they fail"*), Gemini contributes to none of the three: it cannot run code (`none: it reads only`), can reach `127.0.0.1:7701` and write `$HOME` via `find -exec` (Finding 2), and aborts with `no output produced` the moment the model runs `echo`, `git`, `rg`, or a pipe — while `<extras>` leaves a corrupt 0-byte `settings.json` on fresh hosts (Finding 6). Removing Gemini as a reader eliminates `<extras>`, `empty.json`, and the special brief rule without losing any goal capability (keep only `--tmpfs $HOME/.gemini/...` in `FENCE` to hide author Gemini transcripts from other readers).

### Finding 10 [MEDIUM]: Remove `.git` from `<copy>` unconditionally (`--exclude=.git` in `rsync`), removing the manual linked-worktree branch and `-path ./.git -prune`
- **Where:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L18-L28) and [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L123-L125).
- **Concrete failure scenario & why removable:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L25-L32) already omits `.git` for linked worktrees and blind solvers (`git archive`), and passes `--skip-git-repo-check` to Codex (and none of this repository's tests require `<copy>/.git`). Keeping `.git` in `<copy>` causes three concrete failures: (1) committed `AGENTS.md`, `CLAUDE.md`, and frozen `review-loop/<change>/PLAN.md` files remain readable inside `<copy>/.git/objects` (even to Grok `strict` and Claude `Read`), defeating `rsync --exclude`; (2) multi-GB `.git` packfiles are copied into `~/.cache` for every reader per round; and (3) missing the manual check *"If `<repo>/.git` is a file"* leaves `<copy>/.git` pointing into the unprotected main repository.

### Finding 11 [LOW]: Remove Grok's separate "Reading only" (`--sandbox strict`) variant in favor of a single Grok profile always treated as copy-writable
- **Where:** [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L60-L78), [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L95-L98), and [readers.md](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L156-L159).
- **Concrete failure scenario & why removable:** Grok's `--sandbox strict --always-approve` is **not** read-only: as [On a computer for the first time](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L156-L159) notes (`./PROBE_COPY` exists under Grok's `strict`), Grok can run shell commands and modify files in `<copy>`, `/tmp`, and `/var/tmp`. Listing `--sandbox strict` under "Reading only" causes the caller to skip [If the reader may write](file:///home/frank/.cache/rl-recipes/r3/gemini/skills/review-loop/readers.md#L118-L128) (`sha256sum`) even when Grok edits what it is judging, while `strict`'s only extra restriction (blocking reads of `$HOME`) breaks user-installed helpers under `$HOME` and forces `<brief>` onto `argv` (`E2BIG` at 128 KiB).

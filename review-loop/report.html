The stakes

What it is
A new command that sets up a project folder for the office, and the office now guessing which project an agent is in from the folder it started in.
Who relies on it
Every agent on this computer, and on your other computers once you push it. The setup command also writes into your other projects.
What a failure costs
Notes and work logs filed under the wrong project, with nobody noticing. Or your own files changed, or hidden from git, by the setup command.
When we stop
After a round where nothing serious is found and nothing serious or medium needed fixing.

Your decision (to finish the review): accepted

  1. Accept one known limit for repositories that keep their git folder somewhere else? If a project with submodules keeps its git folder outside the project (made with --separate-git-dir), a submodule checked out first in a second working copy gets one project, and a different one once the main copy checks it out too. Git keeps no record of where such a project's main copy is, so there is nothing to work it out from. Recommended: accept it and say so in the notes. You accepted it (27 Oct): skip it unless it is ever needed. None of your projects is set up this way. The alternative changes how every submodule of such a project is filed.
